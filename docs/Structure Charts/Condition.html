Fan-in and fan-out

Fan-in is the number of modules that call a module. Fan-out is the number of modules it calls. Yourdon and Constantine want high fan-in for small shared helpers, since it means one piece of code serves many callers, and moderate fan-out, since a module that calls too many others is hard to follow. parseLine calls six modules and parse calls five, both within the usual rule of thumb of about seven.

What the charts say about the design

Structured Design judges a design by two measures. Coupling is how much one module depends on another, and the couples on a chart are its visible part: fewer and simpler couples mean looser coupling. Cohesion is how closely the statements inside one module serve a single job. A chart shows coupling directly, so these notes read the charts that way.

Every flag travels upward

The charts carry only two flags: found from Matcher.find, and wrapped from isWrappedInBrackets. Both report a fact back to the caller. No module receives a flag that tells it what to do, which Yourdon and Constantine call control coupling and rank below data coupling. The separator that parse passes to splitTopLevel looks like a switch, but splitTopLevel treats ||, && and ; the same way, so it is data. Answer.of also takes a boolean, but it converts that value rather than being steered by it, so the chart draws it as data too.

Two values double as flags

findClosingBracket returns close, which is either an index or -1 when the line ends first. Map.get returns either an answer or null when the check has yet to run. A value that also carries a yes-or-no signal is what Yourdon and Constantine call hybrid coupling. The chart can only draw it as plain data, so the reader has to learn the -1 and null rules from the code. Both follow habits Java programmers already know (String.indexOf returns -1 the same way), so they are worth leaving as they are.

The checks list goes down and comes back up

The constructor hands parse an empty list, and parse adds a check to it each time it reaches a single check. Chart 2 shows the cost: every call of parse passes the list on, though only the last step writes to it, and parse has two outputs, one returned and one written into a list it was given. The shared list is what numbers the checks from left to right across the recursion, so the trade is a fair one.

Three modules repeat the literal scan

stripComment, findClosingBracket and maskLiterals each keep their own record of the open quote and skip the character after a backslash. maskLiterals already returns text of the same length with every literal blanked, so stripComment could mask the line and look for // in the result, and findClosingBracket could expect masked text from its callers. Yourdon and Constantine call this factoring. It would raise the fan-in of maskLiterals and leave one copy of the escape rule to keep correct instead of three.

evaluate(Node, Map) is a transaction centre

A transaction centre is Yourdon and Constantine’s name for a module that looks at the kind of its input and passes it to one of several actions. The switch over Leaf, Not, And and Or is exactly that, which is why every call beneath it on Chart 3 has a diamond. Because Node is a sealed interface, the compiler confirms the switch covers all four kinds.
